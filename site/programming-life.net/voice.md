# voice.md — programming-life.net 文体スペック

このサイトの記事本文の正規仕様。`blog-voice` / `blog-draft` / `blog-quality-gate` がここを唯一の基準として使う。
考え方は task-app の material-writing を借りるが、レジスタはブログ記事用に別物。

## 読者と視点

- 読者: **プログラミング初心者**（「あなた」と呼ぶ）
- 書き手: **一人称なし**。「私」「自分」「当サイト」は使わない
- 基調: **ですます体**。常体（だ・である）・関西弁・命令形単体は禁止

| 許可される語尾 | 禁止される語尾 |
|---|---|
| です / ます / ました / でした | だ / だろ / しろ / せよ |
| しましょう / してみましょう | やで / やな / ちゃう / ワイ |
| ですね / ますね / でしょうか | 〜のである / 〜べきだ（断定命令） |
| してください / しましょう | 「いかがでしたでしょうか」 |

## 記事の型（構造）

```
導入 2段落                … 「この記事でわかること」箱は置かない
  ↓
（目次は SWELL が自動挿入。本文に書かない）
  ↓
H2 ─ capbox（is-style-onborder_ttl2、中身は配下 H3 トピックの箇条書き）
  ├─ H3 ─ 1〜2文の短段落 × 数個 ─ hcb_wrap コードブロック
  ├─ H3 ─ …
  ↓
H2「まとめ」─ capbox + is-style-check_list の箇条書き
  ↓
H3「よくある質問（FAQ）」─ swell-block-accordion（4〜6項目）
```

- 関連記事・メルマガ CTA はテーマ/プラグインが自動挿入するため本文に含めない
- コードブロックは ❌ / ⭕ / 💡 / 🚨 コメント付きの対比形式がこのサイトの型
- 分量の目安: 柱記事 13,000〜20,000 字、通常記事 4,000〜6,000 字

## 定型句（このサイトの語彙。積極的に使う）

- 「初心者がよくつまずくのが〜」
- 「実務では〜」
- 「〜に注意してください」
- 「ここでは、以下のトピックに分けて解説していきます」
- 「〜してみましょう」「〜がポイントです」

## 禁止カテゴリ — AI典型構文

| ❌ NG | ✅ OK |
|---|---|
| することができます | できます |
| これにより | だから / なので / よって |
| 〜と言えるでしょう | 〜です / 〜になります |
| 〜ではないでしょうか | 〜ですよね |
| いかがでしたでしょうか | （削除する） |
| ここでは〜について解説します（定型句以外の前置き） | （削除して本文から始める） |
| さまざまな場面で | （削除するか具体例を書く） |
| 言うまでもありません / あらゆる観点から | （削除するか具体項目を列挙） |

## 禁止カテゴリ — 英語直訳調

| ❌ NG | ✅ OK |
|---|---|
| 〜することは可能です | 〜できます |
| 〜について言及 | 〜について / 〜を紹介 |
| 〜を実施します | 〜します / 〜を行います |
| 〜に関しても同様です | 〜も同じです |

## 書く前の思考矯正（6手順 — 書き始める前と書き直す前の両方で実行）

1. **偏愛語を疑う** — 「設計・仕組み・本質・全体像」「落ちる・壊れる・刺さる・効く」「解像度が高い・深い」が出たら手を止める
2. **実体があるか判定** — 名詞の指示対象を1文で説明できるか。できなければ擦り倒し
3. **比喩に逃げず具体へ** — 「情報が落ちる」ではなく「userId が undefined になると WHERE 句が組み立てられずエラーになる」
4. **構文の癖を直す** — 「AではなくB」の同居は2文へ、「〜という」の入れ子は「〜とは」で定義文へ
5. **動詞・助詞の選択ミスを正す** — 「問題を改善する」→「問題を解決する」等、慣用句の破壊に注意
6. **重言・翻訳調を消す** — 「まず最初に」→「まず」、「返り値を返す」→「返す」

## 5つの不在（表現ではなく思考の欠落として抑える）

| # | 名前 | このサイトでの症状 | 修正 |
|---|---|---|---|
| 1 | 態度の不在 | 全トピックを同じ温度で書く | 重要な所に力を入れ、他は流す |
| 2 | 勇気の不在 | 「〜かもしれません」の保険かけ | 各節で「結局どうか」を1つ言い切る |
| 3 | 省略の不在 | 聞かれてないことまで網羅 | 「今回いらない」と判断して削る |
| 4 | リズムの不在 | 文長が均一 | 長文の後に短文、の緩急をつける |
| 5 | 沈黙の不在 | 全段落に結論を書く | 問いだけ投げて閉じる段落も作る |

**逆方向の要請（ブログでも残すもの）**: 手順の省略は禁止（「同様に」「残りも」「以下略」は NG ワード）。
「なぜこう動くか」はコードの後に必ず書く — 手順の羅列は解説記事ではない。

## セルフチェック（公開前に quality-gate が機械チェックする項目）

- ですます体のみ（常体・関西弁・命令形単体なし）
- AI典型構文・英語直訳調の各 NG 行が出ていない
- 「同様に」「残りも」「以下略」「簡単です」による手順省略がない
- コードブロックに ❌/⭕ 等の対比コメントがある
- capbox / accordion / check_list のマークアップが template と一致
